# 口腔健康 AI 助理

入口：侧栏「AI 助理」、桌面右下角「和小安聊聊」、手机顶部「问小安」，以及图像分析页的「小安结果解读」。默认使用免费的本地 Qwen3.5，也可以选择 DeepSeek 云端服务。文字助理与二维检测 ONNX 模型独立，提供操作引导、情绪支持、健康信息和检查术语解释；不直接读取影像或完成病理诊断。

## 图片结果的陪伴解读

1. 在扫描工作台上传或拍摄图片并确认保存，小安会提示进入图像分析，并保留对应图片的选择。
2. 分析页根据当前图片显示等待、处理中、真实结果就绪、演示或失败状态。已有运行任务会自动刷新进度；影像模型未配置时只展示等待引导，不生成检测结果。
3. 真实分析完成后，患者可以补充不适位置、持续时间等描述，并确认使用当前图片的文字结果。点击「解读结果与就医建议」后才请求模型；不自动发送图片或生成病情结论。
4. 小安在当前页解释模型标签、整理一般就医建议和就诊前准备，也可以继续询问挂号方向、就诊准备或结果的不确定性。紧急症状使用平台既有的直接就医提示。

结果解读只读取所选单张图片的最新已完成、非演示分析；其他图片、旧任务、失败任务和已排除的发现不作为该图片的依据。Crowding、Spacing、Diastema 提供通俗术语释义。该模式不把检测分数传给文字模型，避免将其误用为严重程度或患病概率。没有检测标记也不能排除口腔问题。

切换图片或重新分析会清空解读并取消等待，需要重新确认资料处理说明。小安的眨眼、轻微浮动和思考动画支持系统「减少动态效果」设置。

## 免费本地模式（默认）

本地模式使用 [Ollama](https://ollama.com/download/windows) 运行 [Qwen3.5 2B Q4_K_M](https://ollama.com/library/qwen3.5:2b-q4_K_M)，无需 API 密钥，无按次调用费用。模型在运行它的电脑上处理文本；首次下载需要网络，之后文字问答可以离线运行。实际速度取决于硬件，不代表医疗专用模型。

安装 Ollama 后执行：

```powershell
ollama pull qwen3.5:2b-q4_K_M
```

Ollama 本地服务必须监听 `127.0.0.1:11434`。如果没有自动运行，另开终端执行 `ollama serve`。在 `backend/.env` 设置：

```dotenv
ORALSCAN_ASSISTANT_PROVIDER=ollama
ORALSCAN_OLLAMA_MODEL=qwen3.5:2b-q4_K_M
ORALSCAN_OLLAMA_TIMEOUT_SECONDS=120
```

重启后端并刷新助理页面，即可显示「可以聊聊」和「免费本地模型」。模型未下载或本地服务未启动时，页面如实显示未就绪，不会生成模拟回复，也不会自动改用云端模型。

本地模型与运行组件不提交到 Git。其他开发者需要在自己的电脑上安装 Ollama 并下载同一模型；如将独立运行组件放在 `.local-run/` 中，该目录已由项目忽略规则排除。

后端仅调用固定的本机 `http://127.0.0.1:11434/api/chat`，不经过环境代理，不携带云端密钥。关闭思考输出，仅返回最终回答；单次生成上限 1,200 token，模型上下文窗口设为 32,768。输入按 UTF-8 字节保守控制长度，超过预算时先移除较早的完整问答轮次，保留系统提示和当前问题。

## 可选 DeepSeek 云端模式

在 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 创建密钥并确认服务额度。在 `backend/.env` 设置：

```dotenv
ORALSCAN_ASSISTANT_PROVIDER=deepseek
ORALSCAN_DEEPSEEK_API_KEY=填写你自己的密钥
ORALSCAN_DEEPSEEK_MODEL=deepseek-flash
ORALSCAN_DEEPSEEK_TIMEOUT_SECONDS=45
```

重启后端。密钥只由后端读取，不要放入 `VITE_*`、React 代码、截图或 Git。云端模式下页面会明确告知患者文本将发送给 DeepSeek，数据处理与留存按供应商条款执行。接口依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion)，模型名根据 2026-11-14 文档设置，账号可用模型变化时需相应调整。

## 对话和检查资料

- `GET /api/assistant/status`：返回供应商、模型、本地/云端标记、是否就绪和等待时间；本地模式会查询模型是否已下载，响应不包含密钥。
- `POST /api/assistant/chat`：接收 `provider`（`ollama` / `deepseek`）、`messages`、可选 `scan_id`、`asset_id`、`intent`（默认 `chat`）和必须为 `true` 的 `consent`。`intent=explain_result` 必须同时提供检查与图像编号，后端校验图像归属、最新任务完成状态和演示标记。供应商必须与服务器当前配置一致，避免服务切换后错误沿用旧的数据处理同意。
- 历史从 user 开始、以 user 结束，user/assistant 交替；最多 21 条、总计 24,000 字符，单条患者输入最多 3,000 字符。本地模式另有输入字节预算，防止推理服务截掉系统提示。
- 患者选择检查并勾选「结合这份检查的文字摘要」后才附带资料。改变检查或摘要开关会开始新对话，并重新确认处理说明。
- 摘要仅包含图像/网格数量、分析状态、每项资产最新成功任务中的发现标签、分数和复核状态；不发送文件、文件名、元数据身份字段、路径或检查编号。旧任务、失败任务、示例结果和已排除的发现不发送；结果解读模式另排除评分数值，最多 30 条发现和 30 项资产状态。
- 对话不写入应用数据库或浏览器存储，离开助理页会结束本次对话；日志不记录患者文字。云端服务的处理行为独立于本地应用。
- 提示词要求先承接情绪，再解释可能原因、不确定性和下一步；不冒充医生，不提供确定诊断、处方或个体化剂量。出现危险症状时优先提示急诊评估。网格质量与模型分数不能用于推断患病概率。
- 超时、服务未启动、模型缺失、限流、额度不足及回复截断均有独立处理。截断的医学回答不会展示成完整建议。
- 呼吸或吞咽困难、面颈部迅速肿胀、持续大量出血等明确危险描述会优先返回固定就医提示，不调用模型猜测病名，并在页面注明提示由平台直接提供。规则会排除常见的否认表述，但不能覆盖所有语言表达，不能代替专业分诊。
- 对验证中发现的少数明确保证疼痛或疗效的说法，会改为标注来源的平台健康提示。这只是有限的措辞检查，不代表已自动审查所有医学内容。
- 已知的上传、摄像头采集、三维导入、历史查询和报告导出步骤由平台直接提供并标注来源，避免轻量模型虚构 PDF 上传、屏幕录制或自动诊断功能。一般健康问答仍由所选模型生成。

系统提示不能保证模型输出的医学准确性。轻量本地模型用于开发和辅助理解，面向患者使用前仍需专业审核，以及项目现有的身份授权、访问控制和数据保护工作。目前项目适用于本地开发。

## 验证

前端：`pnpm build`、`pnpm lint`、`pnpm test`。

后端：`.venv/Scripts/python.exe -m pytest tests/test_assistant.py -q`。自动测试使用替代传输，验证本机/云端路由、密钥隔离、患者同意、摘要最小化、禁止静默切换、超时和截断处理。安装模型后，还需通过页面实际测试中文安抚、症状解释和紧急就医提示。
