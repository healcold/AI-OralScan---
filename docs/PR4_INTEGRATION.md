## 这次怎样处理

开始整合时，来源分支已经提交 `09c6ccc`，把 main 合入并解决了文本冲突。本次在这个提交上检查整合结果，保留账号权限，也保留主分支的并发限制、上传暂存和失败恢复逻辑。

另外补上了部署时遇到的 HTTP 上传问题：图像采集统一使用 `crypto.getRandomValues` 生成 UUID v4，不再依赖仅在安全上下文中可用的 `crypto.randomUUID`。浏览器回归测试会主动移除 `randomUUID`，再走上传、保存和私有记录检查流程，避免只在 localhost 上成功。

## 旧记录怎么处理

维护者决定：原有记录作为旧测试数据保留，不分配给新账号。数据库升级给这些记录保留空的 `owner_id`；账号列表和直接链接都不提供访问。它们没有被删除，也不会自动归给第一个注册用户或管理员。

## 验证范围

- 后端完整测试：覆盖账号隔离、旧数据库迁移、上传、删除恢复、报告、推理及并发回归。
- 前端单元测试、TypeScript/Vite 构建和 ESLint 检查。
- 浏览器流程：注册登录、双账号隔离、图片上传、摄像头模拟、三维导入、报告及失败提示。

浏览器测试使用临时数据库、模拟图片与测试模型，不代表线上真实模型和摄像头设备已验收。

## GitHub 合并与服务器发布是两件事

本次处理源码与 PR，不操作云服务器。部署工作日志描述的是当天早先的 HTTP 演示环境；合并后的版本新增账号隔离，两者是不同阶段的状态。

发布账号版本前仍需备份数据库和上传目录、核对服务器临时修改，并配置 HTTPS。正式部署设置 `ORALSCAN_SECURE_SESSION_COOKIE=true`，仅在 HTTP 下设置它会导致浏览器无法正常携带该登录 Cookie。UUID 兼容补丁只解决 ID 生成，不会给 HTTP 增加加密或摄像头权限。

云端管理账号需要在与 systemd 服务相同的数据库配置下创建，否则命令行默认数据库可能与网站数据库不是同一份。不要把真实密码、Cookie 或业务数据提交到仓库。
