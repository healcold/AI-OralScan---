# 2026-11-15 工作日志｜AI OralScan · 口腔影像工作台

今天最想解决的事很简单：我电脑上能开的东西，发给同学之后也得能打开。后来发现，能打开、能用摄像头、能看到自己的病例、改完界面还能放心上线，是四件不同的事。问题用我当时聊天的口吻整理，回答补上了实际操作和检查结果。

## 一、GitHub 的代码到华为云，到底走到哪了？

**我问：GitHub 里面又更新了，我已经看不懂了。现在我们在干什么，多久能弄好？**

**答：** 我们在把 GitHub 上的代码变成华为云上实际运行的网站。先下载分支快照，把源码解压到预览目录，再构建前端、用独立数据库启动后端做检查。通过之后才切换正式入口。下载时终端显示进度到 100%，解包检查显示 `SOURCE_OK`，随后 Vite 输出了 `dist/`。这些是下载和构建已经完成的证据。整次上线还包括验证后端、切换 Nginx 和从公网复测，所以不能只看构建用了几秒就说弄好了。

**我问：所以已经拉下来了？我看终端上怎么有那么多黄色的字？**

**答：** 已经拉下来了，这一轮用的是 GitHub 的压缩包。Vite 提示某个 JavaScript 文件超过 500 kB，意思是以后可以做分包，让首次加载更轻。终端最后有 `built in …`，产物也确实存在，说明这次构建成功。临时后端是在 `127.0.0.1:8001` 上跑的，正式 API 在 `127.0.0.1:8000`，用 Nginx 转发给浏览器。

**我问：GitHub 上 PR、Issue 和分支到底有啥区别？结合我这个项目说。**

**答：** 分支是独立做改动的地方。比如口腔照片识别和登录功能可以先在分支上整理，再通过 PR 把改动和测试结果交给人审查。Issue 适合记问题或计划，比如「小安挡到患者看病例」；解决这个问题的代码放在 PR 或提交里。今天承接了患者账号和私有检查记录的 [PR #4](https://github.com/healcold/AI-OralScan---/pull/4)，整合了中文密码找回，还合入了改善 Windows 启动和认证报错的 [PR #5](https://github.com/healcold/AI-OralScan---/pull/5)。部署前端之前先核对 `main` 的提交，这样线上版本能追到对应源码。

**我问：GitHub 单个文件是不是最多 150 MB？现在天天往上放，后面会不会满？**

**答：** 普通 Git 推送时，超过 50 MiB 的单文件会警告，超过 100 MiB 会被 GitHub 拒绝。源码、文档和依赖锁文件适合直接进 Git。以后更大的模型权重可以看 Git LFS 或 Release，真实数据库、用户影像和本机依赖目录分别留在适合的存储里。仓库历史也会累积，提交过的大文件仅从当前目录删掉，历史里仍然有副本。 [GitHub 大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

**我问：你直接操作了我的华为云吗？**

**答：** 有，操作入口是 Chrome 里已经打开的华为云 VNC。期间有一轮切换触发了回退；下一轮把 Nginx 重载和新页面可用之间的等待纳入检查，成功标记才出现。后端重启时看到几次 `curl: (7)`，随后重试拿到 `/api/health` 的 `status: ok`，说明端口在后续尝试中已经开始接收请求。空 JSON 调用密码重设接口得到预期的 `422`，说明请求到达了接口校验，没有重设任何人的密码。

## 二、网站能开、摄像头能用，中间差在哪？

**我问：我同学发个托管网站就随便能打开，我这个发过去却超时。是华为云没设好吗？**

**答：** 截图里有浏览器能打开页面，也有浏览器报 `ERR_TIMED_OUT`。只凭超时截图判断不了请求走的是 HTTP 还是 HTTPS，也定位不了是哪一段网络在等。托管平台给同学的链接本身已经是 HTTPS，我们当时分享的是华为云的 HTTP 公网 IP。我们检查了安全组的 IPv4 TCP 80 规则，后来补了 443，并从服务器外用完整的 `https://` 地址请求网页和 API。测试能拿到 200，才确认公网这条路径走通了。

**我问：手机 Chrome、Edge 会不会自己把 HTTP 变 HTTPS？到底咋测？**

**答：** 浏览器是否尝试升级连接会受版本和设置影响。要分清是哪一段出了问题，可以直接测试明确写出的协议和端口，也可以用 `curl` 分别请求。后来我们给公网 IP 装了可信证书，分享时就发完整的 HTTPS 链接。手机进站后还要给这个站点摄像头权限。录屏里的提示对应浏览器摄像头所需的安全环境，所以页面能加载，摄像头权限也可能仍是灰的。临时演示可以先用手机相机拍照，再从相册上传。

**我问：买域名、备案有点麻烦。先用 IP 能不能弄？自动续期要钱吗？**

**答：** 今天把域名方案搁置，实际用的是 Let’s Encrypt 的公网 IP 证书。签发和续期免费，每张 IP 短期证书有效 160 小时，也就是 6 天 16 小时。华为云主机按自己的账单续费。 [Let’s Encrypt IP 证书说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)

**我问：优先级填啥？第四步、第五步各在干什么？**

**答：** 华为云安全组新增一条入站规则，优先级填 `1`，跟原有 80 规则同级，允许 IPv4 TCP 443，来源 `0.0.0.0/0`，保留原有的 TCP 80。Certbot 通过 `webroot` 把验证文件放到验证目录，Let’s Encrypt 会从公网读取。看到 `Successfully received certificate` 后，才把证书链、私钥路径和 443 监听加到 Nginx。先跑 `nginx -t`，通过后重载 Nginx，再用标准证书校验访问 HTTPS。申请时出现的第二个邮箱选项是是否愿意与 EFF 分享邮箱，可以自己选择。 [Certbot IP 证书申请说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

**我问：为什么显示 6h？那我现在做什么能让成功率变高，它能维持两个月吗？**

**答：** 那个 `6h` 是离 Certbot 下次检查的时间。证书到期时间单独看证书。今天确认 `snap.certbot.renew.timer` 处于活跃状态、模拟续期显示成功，且续期配置里有重载 Nginx 的钩子。只要续期能持续成功，同一个 IP 地址就能长期用 HTTPS。实际运行依赖服务器继续运行、公网 IP 保持绑定、80 端口的验证路径能访问。模拟通过验证了当时的申请流程，将来首次真正续证还有待观察。

## 三、账号、数据库和小安到底在服务器上做什么？

**我问：登录和扫描的数据是直接存在我那台华为云机器上吧？**

**答：** 这次部署用的是本机 SQLite，服务配置指向 `/var/lib/ai-oralscan/oralscan.db`。账号、登录会话、扫描和报告等有各自的表，上传图片等私有文件保存在 `/var/lib/ai-oralscan/private`。正式数据的位置与 `/opt` 下的源码和前端构建分开。患者登录后只能通过自己的账号访问自己的检查。

**我问：为啥命令是红的？我咋没看到手机号，别人注册我也没查到？**

**答：** 红色是终端把 `grep` 匹配到的变量名或配置行高亮了。真正需要处理的是后面那句 `sqlite3: command not found`，系统缺的是命令行程序。服务器已有 Python 的 `sqlite3` 模块，所以可用它以只读方式打开数据库。查 `PRAGMA table_info(accounts)` 看到的是字段结构，注册手机号记在 `username` 字段；查记录才会看到账号。别人完成注册后重新查询，后来确认新账号出现了。密码只以哈希和盐保存，查库无法拿到用户原密码。公开日志里也不放真实账号、检查结果或任何凭据。

**我问：忘记密码这块怎么弄？用中文答案到底能不能用？**

**答：** 新账号可以在注册时选择或填写找回提示，再设置私密答案。之后在忘记密码页填写手机号、同一个提示和答案，核对成功后设置新密码。测试覆盖了中文提示和中文答案、填错提示被拒绝、重设后使用新密码登录。旧账号如果注册当时没有设置找回答案，需要联系维护者。

**我问：小安能不能直接部署在服务器上？我感觉这个负载有点大。DeepSeek 和本地千问谁强？**

**答：** 小安的页面和 API 继续在华为云上跑，文字推理可以交给本地 Ollama 或 DeepSeek。仓库给的本地示例是量化的 Qwen3.5 2B。小云机上把大模型推理交给 DeepSeek，可以减少本机 CPU 和内存压力，换来网络依赖和调用费用。中文长回复、复杂指令和解释的效果用同一组题对照最清楚，不能只用参数量或几条示例给出全面排名。图像标记仍是独立的影像模型流程。小安在用户同意后可解释文字摘要，原始图片不发给文字模型。

**我问：我 Key 建好了，钱也充了，接上没？为啥上面写连接失败，下面又 `status: ok`？**

**答：** 今天把 DeepSeek 配置放到后端的 systemd 环境文件里，使用 `deepseek-flash`，密钥由后端读取。重启服务后最早几次探测发生在端口开始监听前，重试以后 `/api/health` 返回了 `ok`。健康接口只说明应用能响应。接入时另外通过小安页面用虚构问题实际拿到了模型回答，才确认那次请求确实走通了 DeepSeek。最后的线上复核查了 API 健康和未登录访问限制，没有再次发起付费模型调用。

## 四、手机和电脑都能舒服地看病例了吗？

**我问：小安会挡到患者看病例，我感觉手机端和电脑端 UI 都有点瑕疵。看着咋这么挤？**

**答：** 录屏里，手机上的长回复被挤进输入框上方一小块区域。窄屏分析页还曾把小安解读排在影像前面，较宽屏幕则有右下角悬浮入口。现在影像和分析发现排在前面，小安解读在下方；入口移到顶部，手机和横屏窗口用页面滚动来读长回复，新回复从开头显示。要接着聊可以跳回输入框，要看检查或报告也能从聊天页直接过去。窄屏的筛选、日期和报告操作一并调整了宽度、换行和点击区域。

**我问：不同设备都测试了吗？以人用起来舒服为准。**

**答：** 浏览器跑了 7 组尺寸：`320×568`、`390×844`、`430×932`、`768×1024`、`844×390`、`1366×768`、`1920×1080`。逐项检查了病例详情能打开、影像排在解读上方、长回复开头看得见、页面没有横向溢出、报告按钮能滚动到并操作。在 320 px 窄屏实际生成并读取了 PDF。前端 28 项测试和浏览器 11 项测试都通过了。浏览器使用的是测试账号、合成图片和模拟 AI 回复，这一轮设备覆盖来自窗口模拟，手机真机与各浏览器组合未逐一复测。

**我问：提交 GitHub 和华为云同步都做了吗？我 VNC 还开着。**

**答：** 界面改动提交 [`309a868`](https://github.com/healcold/AI-OralScan---/commit/309a868525410105843372078175591368fa0cb5) 已推到 `main`。华为云从同一个提交下载前端到单独目录，按锁文件安装并构建，备份 Nginx 配置后才切换前端目录。旧前端文件保留以便回退，也让已打开页面还能加载旧版资源。终端显示 `UI_BUILD_309A868_OK` 和 `UI_DEPLOY_309A868_OK`。公网首页、病例、分析、报告和小安的入口返回新版 HTML，JavaScript 和 CSS 文件哈希也和本地构建一致。

**我问：你确定做好了吗？华为云很重要，证书、数据库、API 别做坏。**

**答：** 最后用只读方式复核了一遍。与发布前备份逐字对比，Nginx 站点配置唯一的变化是前端目录。生产后端仍从原目录运行。公网 TLS 连接正常通过证书校验，Certbot 定时器有效、续证后重载钩子存在。用后端服务账号打开 SQLite 做 `PRAGMA quick_check(1)` 得到 `ok`，账号、会话、扫描和报告所需的表都存在。公网 `/api/health` 返回 `200`，未登录访问账号、扫描和小安状态接口按预期返回 `401`。这次复核没有写入真实病例，也没有再次调用付费接口。
