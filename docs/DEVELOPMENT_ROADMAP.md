# 开发路线与阶段门

每阶段先检查现有代码，完成真实功能和相应测试后暂停等待用户验收；不提前实现下一阶段。Phase 0 仅交付设计。

| 阶段 | 范围 | 关键验收及依赖 |
|---|---|---|
| 1 | React/Vite/TypeScript 工作台、导航、三种入口及明确标记的演示状态 | 页面与响应式交互、构建和类型检查；先解决 npm 缺失，参考页面待查看 |
| 2 | FastAPI、SQLite、会话/资产、私有文件存储、前后端连接 | CRUD、资产关联、安全存储及 API/数据库测试 |
| 3 | 图片上传、方向处理、摄像头采集与资产保存 | 格式、异常、权限、帧采集与资源释放测试；需要可用摄像头 |
| 4 | STL/OBJ/PLY 导入、Three.js 查看、Trimesh 基础解析及可复现 fixtures | 三格式、交互、单位 unknown、损坏及资源限制测试；不声称疾病识别 |
| 5 | 模型适配器、YOLO 解码、类别感知 NMS 与坐标映射 | 缺模型状态、真实模型契约验证、单元/API 测试；没有口腔模型时不伪造结果 |
| 6 | 独立网格质量和几何分析 | 指标及无效体积原因、原件保留、合成模型测试 |
| 7 | 多模态汇总、历史、PDF/JSON 报告 | 部分失败保留、坐标隔离、版本溯源与免责声明、端到端测试 |
| 8 | 系统测试、性能检查、安全检查与部署说明 | 实测四种流程、异常、安全及构建测试；未测试项目如实报告 |

专业扫描仪接入属于未来 Phase 9，不属于当前 MVP；须取得实际设备、厂商 SDK 和文档后单独确认。Phase 1 之前须用户验收 Phase 0；依赖安装、网络及设备准备按实际需要处理。
